# Rot Check — native iOS app

A real SwiftUI app. No WebView, no HTML, no bridge. The card stack is a `ZStack`
driven by `DragGesture`, the meter runs off a wall-clock timer, ads come from
the Google Mobile Ads SDK, and there is no server anywhere.

> **Not compiler-verified.** Written on Windows with no Swift toolchain. The
> game logic is a direct port of the tested web build, but expect a handful of
> compile errors on first build. The SDK-facing files (`AdManager`,
> `NativeAdCard`, `ConsentManager`) target Google Mobile Ads **v12** and UMP
> **v3** naming and are the likeliest spots.

---

## What's here

```
Config.swift           bundle ID, product/leaderboard/ad-unit IDs, share URL — change things here
RotCheckApp.swift      entry point; launch sequence (consent → ads), scene-phase pause
Theme.swift            palette, type, shared surfaces
Deck.swift             Term / Sponsor / ranks (no content — see deck.json)
deck.json              the content, 606 terms — generated by tools/make-deck.py
DeckLoader.swift       bundled → cached → remote deck, no app update needed for new terms
GameModel.swift        the whole game: Endless, Daily Rot, High Rot, scoring, metrics
CardView.swift         swipeable card; sponsor card picks native ad or house creative
NativeAdCard.swift     AdMob native ad rendered as the in-deck sponsor card
AdManager.swift        house ads + AdMob (interstitial, rewarded, native) behind one protocol
ConsentManager.swift   UMP consent (GDPR/UK/CH) and ATT, sequenced correctly
Store.swift            Remove Ads via StoreKit 2
GameCenter.swift       two leaderboards, auth, submit, present
Reminders.swift        "Today's Rot is ready" local notification
ShareCard.swift        the emoji result grid and share text
ContentView.swift      router, title, house-ad overlay, debug metrics drawer
GameView.swift         HUD, card stack, controls, game over (both modes)
SettingsView.swift     Remove Ads, reminder, leaderboards, privacy options
PrivacyInfo.xcprivacy  app-level privacy manifest (required)
Info.plist             AdMob ID, ATT string, SKAdNetwork IDs, orientation
```

Two modes. **Endless** is the ad engine: meter, revive, double-your-score,
sponsor cards in the deck. **Daily Rot** is the growth engine: 20 fixed cards
seeded from the date, identical for everyone, one attempt, an emoji grid to
share. It's deliberately ad-free inside the run so the result stays fair and
postable — it earns through the interstitial after, and by bringing people back
who then play Endless.

## 1. Xcode project (Mac, day one)

1. **Xcode → File → New → Project → iOS → App.** Product Name `RotCheck`,
   Interface SwiftUI, Language Swift, Organization Identifier `com.tareque`
   (so the bundle ID is `com.tareque.rotcheck` — matches `Config.bundleID`;
   change both if you want a different one).
2. Delete the generated `ContentView.swift` and `RotCheckApp.swift`.
3. Drag every file from `ios/RotCheck/` into the navigator — Swift, `deck.json`,
   `PrivacyInfo.xcprivacy`, `Info.plist` — with **Copy items if needed** and the
   RotCheck target ticked. Xcode picks up `Info.plist` and the privacy manifest
   automatically when they're in the target.
4. Target → General → **Minimum Deployments: iOS 16.0**. Device Orientation:
   Portrait only.
5. Target → Signing & Capabilities → **+ Capability**: add **Game Center** and
   **In-App Purchase**.
6. **Build and run.** It plays on house ads before any package is added.

### Packages (File → Add Package Dependencies)

| Package | URL | Notes |
|---|---|---|
| Google Mobile Ads | `https://github.com/googleads/swift-package-manager-google-mobile-ads.git` | v12+. `AdManager` and `NativeAdCard` compile against it automatically via `canImport`. |
| User Messaging Platform | `https://github.com/googleads/swift-package-manager-google-user-messaging-platform.git` | v3+. Consent for EEA/UK/CH. Without it those regions get Limited Ads only. |

Add both, build again. Nothing else changes.

### StoreKit testing without App Store Connect

File → New → **StoreKit Configuration File** → add a **Non-Consumable** with
product ID `com.tareque.rotcheck.removeads`, price 2.99. Then Scheme → Run →
Options → StoreKit Configuration → pick it. Purchases now work in the simulator.

### Fonts (optional but recommended)

`Fonts` falls back to system faces if these aren't bundled, so the app looks
deliberate either way. To ship the real ones: download
[Anton](https://fonts.google.com/specimen/Anton),
[Bungee](https://fonts.google.com/specimen/Bungee),
[Archivo](https://fonts.google.com/specimen/Archivo) (Regular + Bold), and
[DM Mono](https://fonts.google.com/specimen/DM+Mono); drag the `.ttf`s in; add
them under Info → **Fonts provided by application**. Expected PostScript names:
`Anton-Regular`, `Bungee-Regular`, `Archivo-Regular`, `Archivo-Bold`, `DMMono-Regular`.

### App icon

```bash
python tools/make-icons.py
```

Drag `icon-512.png` (or a 1024 export) into Assets → AppIcon.

## 2. First device session — what to actually check

Plug in the iPhone by cable and run on it. The simulator can't do haptics and
the drag physics feel wrong through a video pipe. Then:

- **Drag threshold** (85 pt in `CardView`) and **drain speed** (`drainBase` in
  `GameModel`) — tune by feel. This is the one thing that couldn't be tested.
- **Sponsor card drag.** The native ad view is UIKit inside SwiftUI; confirm a
  drag across it still swipes and a tap on the CTA still opens the ad. If drag
  is swallowed, the FAKE/REAL buttons are the fallback — but check.
- **Backgrounding** mid-run pauses the meter (and the Daily stopwatch).
- **Daily Rot** shows the same 20 cards on two devices on the same day.
- The result grid shares cleanly to Messages.

## 3. Before submission

**Accounts and IDs**
- [ ] AdMob: create the app, three units (interstitial, rewarded, native).
      Put the app ID in `Info.plist` **and** `Config.admobAppID`; unit IDs in `Config`.
      **Shipping with Google's test IDs can get the account flagged.**
- [ ] `Info.plist` → `SKAdNetworkItems`: replace with the full current list from
      the [AdMob quick start](https://developers.google.com/admob/ios/quick-start).
- [ ] App Store Connect → Game Center: leaderboard `com.tareque.rotcheck.endless`
      (Classic) and `com.tareque.rotcheck.daily` (**Recurring, daily reset**).
- [ ] App Store Connect → In-App Purchases: `com.tareque.rotcheck.removeads`,
      non-consumable, $2.99.
- [ ] `Config.shareURL` → the real App Store link (visible in ASC before launch).
- [ ] Optional: host `deck.json` somewhere static and set `Config.deckURL`.
      Bump `VERSION` in `tools/make-deck.py` on every content change.

**Listing**
- [ ] Age rating **13+** (new questionnaire — answer "infrequent/mild" for
      crude humour; the deck is audited for 13+ by `make-deck.py`).
- [ ] Privacy policy URL — mandatory; must disclose AdMob's data collection.
- [ ] App Privacy answers matching `PrivacyInfo.xcprivacy` (Device ID,
      Advertising Data, Product Interaction — used for third-party advertising).
- [ ] 6.9" screenshots, 1320 × 2868, up to 10. First three carry the pitch.
- [ ] Name **Rot Check** · subtitle *Real slang or AI slop?* · keywords:
      brainrot, slang, gen z, quiz, rizz, skibidi, sigma, aura, meme, trivia.

**Then:** Product → Archive → Distribute → TestFlight → a few days on real
phones → Submit.

## Publishing to the App Store

$99/yr Apple Developer Program, and a Mac running macOS 15.6+ for Xcode 26
(mandatory for all submissions since April 2026). Individual enrolment is fast;
organisation enrolment needs a D-U-N-S number and can take weeks.

**What gets an app like this rejected**
- Guideline 4.2 (minimum functionality) — the reason this is native, not a wrapper.
- Privacy answers that don't match the SDKs actually shipped.
- Missing `NSUserTrackingUsageDescription` while linking AdMob.
- Test ad unit IDs left in the release build.
- Age rating that doesn't match the content or the marketing.

## Google Play (later)

Play has no equivalent of 4.2, so wrapping the web build with Capacitor is a
legitimate shortcut there. Note: new *personal* Play accounts must run a closed
test with 12 testers for 14 continuous days before production access.

## Content notes

`deck.json` has 295 real terms and 311 invented ones. The build script
rejects duplicates, over-long terms, and anything on the 13+ banned list.

Real-term accuracy is a judgement call on a moving target. The ones most worth
a second opinion before launch are the newer Gen Alpha entries (`six seven`,
`huzz`, `bruzz`, `tuff`, `icl`, `big back`, `clanker`) and the Italian brainrot
character spellings, which vary across the internet. One wrong "real" is a
one-star review; the note text for each term is meant to make review fast.
